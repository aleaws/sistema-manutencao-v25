Manutenção interna no computador e celular

O GitHub Pages entrega o aplicativo. O Supabase guarda os registros confirmados. O celular guarda os envios enquanto estiver sem internet. Seu notebook pode ficar desligado.

O pacote está preparado, mas não foi publicado nem ativado no seu projeto. Execute os passos abaixo. Não precisa instalar Python para esta versão.

1. Preparar a base online

  1. Acesse o painel do Supabase e abra o projeto utilizado pelo V25.
  2. Abra SQL Editor → New query.
  3. Abra INSTALAR_BANCO.sql do pacote no Bloco de Notas. Copie o conteúdo inteiro para a consulta e clique em Run. Este arquivo cria somente objetos mi_. Ele não apaga nem modifica tabelas do V25.
  4. Abra Authentication → Users → Add user → Create new user. Cadastre seu e-mail e uma senha forte. Confirme o e-mail no cadastro manual se houver essa opção. Se sua conta já existir, não crie novamente.
  5. Abra PRIMEIRO_ACESSO.sql no Bloco de Notas. Troque apenas SEU_EMAIL_AQUI pelo e-mail cadastrado, mantendo as aspas.
  6. Execute esse segundo arquivo em uma nova consulta no SQL Editor. Isso libera sua conta como gestão.

O usuário salvo no navegador pelo V25 não substitui a autenticação deste novo sistema. As contas precisam existir no Supabase Auth.

2. Publicar junto do V25 no GitHub

  1. Acesse o repositório onde o V25 já está hospedado.
  2. Confira em Settings → Pages qual pasta é publicada. Se for a raiz, coloque a nova pasta na raiz. Se for /docs, coloque dentro de /docs. Se usar Actions, inclua a pasta na saída publicada desse projeto.
  3. Escolha Add file → Upload files e arraste a pasta manutencao-interna para esse local. Preserve a pasta: o novo index.html precisa ficar dentro dela, não em cima do index do V25.
  4. Confirme o envio em Commit changes e aguarde a publicação do Pages concluir.
  5. Abra o endereço do V25 acrescentando /manutencao-interna/ à pasta base do site. Se o V25 abre por um arquivo HTML, retire o nome desse arquivo antes de acrescentar a nova pasta.

Exemplo ilustrativo: https://usuario.github.io/repositorio/manutencao-interna/. Esse exemplo não é seu endereço real.

Se desejar, depois adicione um botão no V25 apontando para manutencao-interna/. O pacote não altera o menu atual.

3. Primeiro acesso e celulares

  1. Com internet, abra o novo endereço e entre com o e-mail e senha criados no Supabase.
  2. Espere Sincronizado. O sistema prepara a cópia para uso offline. Isso só funciona pelo site HTTPS ou em localhost de teste; abrir o arquivo por duplo clique não ativa o offline.
  3. No Chrome do celular, use o menu de três pontos → Instalar aplicativo ou Adicionar à tela inicial. No iPhone, use o Safari → Compartilhar → Adicionar à Tela de Início.
  4. Cadastre máquinas, dispositivos, responsáveis e planos no sistema.
  5. Para a equipe: crie as contas em Authentication → Users no Supabase. Depois, na aba Equipe deste aplicativo, informe o e-mail, nome e perfil.
PerfilPode fazer
SolicitanteAbrir OS e consultar registros internos.
ManutençãoAbrir OS, acompanhar suas atribuições, encaminhar, concluir e registrar itens.
GestãoGerenciar todas as OS, equipamentos, planos, acessos, relatórios e conferências.

4. Testar antes de adotar na fábrica

  1. Crie uma OS de teste com internet e confirme no outro aparelho.
  2. Ative modo avião no celular e desative o Wi-Fi. Abra outra OS.
  3. Confirme que ela aparece como Pendente de envio. Feche o aplicativo e abra de novo sem internet: o registro deve continuar lá.
  4. Desative modo avião e reabra o aplicativo. Aguarde a fila de envios zerar.
  5. No notebook, confira que a OS chegou uma única vez.
  6. Teste transferência entre responsáveis, fechamento, preventiva e relatório Excel.

5. O que significa cada estado

EstadoSignificado
Salvo no aparelho / pendenteNão foi confirmado pelo servidor. Os outros aparelhos ainda podem não enxergar.
SincronizadoO servidor confirmou os envios deste aparelho e a base foi consultada.
Precisa de revisãoHouve conflito ou recusa. Revise a proposta na aba Sincronização.

6. Limites importantes

  • Com aplicativo aberto, tenta sincronizar ao reconectar, ao voltar à tela e a cada 15 segundos. Sincronização em segundo plano depende do navegador; se estiver fechado, pode precisar reabrir.
  • O primeiro login precisa de internet. Uma sessão expirada pode exigir entrar novamente. A fila permanece na conta original.
  • Não há notificação push com tela bloqueada. Os avisos e som funcionam com o aplicativo aberto; ative o som em Meus avisos.
  • Não limpe os dados do navegador nem desinstale o aplicativo com envios pendentes. O navegador pode eliminar armazenamento sob pressão de espaço; faça cópias e mantenha espaço livre.
  • O relatório Excel inclui somente a cópia confirmada da base. Registros pendentes não entram. A competência de gastos é o mês de recebimento no servidor, no fuso de Brasília.
  • Confirme a baixa no ERP somente depois de conferir todos os aparelhos. O envio ao ERP continua manual.
  • OS fechadas não reabrem nesta versão. Gastos confirmados não têm estorno/edição. Não inclui anexos, estoque ou importação automática do V25.
  • A base armazena um documento transacional compartilhado, adequado ao piloto de equipe pequena. Para alto volume de histórico, evolua para tabelas por entidade e paginação antes de ampliar o uso.
  • Os dados ficam no plano Supabase existente; limites, disponibilidade e eventuais cobranças dependem desse plano. O pacote não contrata serviços nem altera o plano.

7. Backup e atualização

Use Sincronização → Baixar cópia de segurança. O JSON contém a cópia consultada e a fila pendente, sem senhas. A restauração importa apenas os envios pendentes da mesma conta; não substitui a base online. A gestão deve manter também exportação/backup das tabelas mi_store, mi_members e mi_receipts no Supabase.

Ao atualizar arquivos no GitHub, incremente a versão do cache no sw.js. Feche todas as abas e reabra para ativar a atualização, depois de sincronizar. Não altere o caminho da pasta nem os nomes do armazenamento, pois a fila está vinculada ao endereço.

8. Estrutura separada

O config.js já tem a URL e chave publicável encontradas no arquivo do V25. Não contém senha nem chave de administrador. Nunca coloque uma chave service_role no GitHub. A proteção de acesso é feita pelas funções do servidor, com acesso direto às tabelas bloqueado para usuários do site.

O serviço offline só controla a pasta manutencao-interna/. Se o V25 já tiver um serviço offline na raiz que intercepte todas as páginas, valide o novo endereço e ajuste a integração com apoio técnico, sem apagar os dados do V25.
